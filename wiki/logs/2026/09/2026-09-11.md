## Mass-shell contract failed for Pipeline B under guard v4

### Observed

- `execute_model4_post_training.py` passed 2022 Pipeline A and then raised
  `ValueError: Generated output violates the mass-shell contract` on 2022
  Pipeline B, at `generation/model4.py`.

### Cause

- `E` is reconstructed as `sqrt(px^2+py^2+pz^2+m^2)`, so the residual
  `E^2-px^2-py^2-pz^2-m^2` is exactly zero in real arithmetic and is pure float64
  rounding in practice. That rounding scales as `2.5*eps*E^2`, so the fixed
  `1.0e-6 GeV^2` threshold was an implicit ceiling at about 42 TeV.
- Guard v4 is train-fitted, so `empirical_support.action` resolves to
  `diagnostic_only` and the observed FLUKA min/max no longer rejects. Only
  non-finite, `E<=10`, and `pz<=0` still reject, leaving `pz` unbounded above.
- Pipeline B inverts `pz` with `exp`, which grows exponentially in model space, so
  it reaches the 42 TeV rounding ceiling at only +3.0 to +3.6 sigma depending on
  the campaign. Pipeline A inverts Box-Cox, which grows polynomially and needs
  +11.6 to +25.7 sigma, which is why A passed and B failed.

### Changed

- Replaced the absolute mass-shell and scoring-plane thresholds with relative
  tolerances (`1.0e-12`), keeping an absolute floor on the scoring plane. The
  relative residual stays near `1e-16` from 100 GeV to 500 TeV, so the check is now
  scale-free and still four orders of magnitude above the noise floor.
- Both contract errors now report the offending residual, the tolerance, and the
  energy at the worst row, instead of failing with no numbers.
- Added `empirical_envelope_excursion` to the generation manifest: per-feature
  envelope bounds, generated min/max, row counts outside, and the excursion
  measured in envelope widths.

### Decision or note

- The tolerance fix alone is not a resolution. It stops the crash but would let
  Pipeline B ship muons far beyond anything FLUKA produced; at +5 sigma the 2022 B
  inverse reaches about 523 TeV against an observed envelope of 5.1 TeV. Whether
  that extrapolation is acceptable is a physics decision, not a numerical one, and
  it is still open.
- The excursion diagnostic exists so that decision is made against recorded
  numbers rather than being hidden by a silently passing contract.

## Train observed-FLUKA envelope rejects again

### Changed

- `fit_reference_guard` gained `empirical_support_action`, default
  `operational_reject`. The train-fitted observed FLUKA min/max envelope now
  rejects generated rows outside it, as guard v3 did. `diagnostic_only` stays
  available by passing it explicitly.
- The artifact records `empirical_support.action_source` as `caller_policy` for a
  train-scoped guard and `production_only_scope` for an all-clean guard.
- `_validate_guard_role` no longer hardcodes `diagnostic_only` for validation and
  test. It accepts either recorded action there and still forces
  `operational_reject` for `muondis`.
- `create_model4_reference_guards.py` skip-existing now expects the rejecting
  train envelope, so stale v4 artifacts are refitted rather than reused.

### Decision or note

- Leakage is controlled by `fit_scope`, not by the envelope action. A train-fitted
  envelope carries no validation or test information whichever action it declares,
  so making it reject is a scientific policy choice and not a leakage regression.
- This restores the property that silently protected all twelve baseline runs: with
  `pz` capped at the observed 4.5-5.1 TeV, the mass-shell residual stayed 124x to
  231x below its threshold. Removing the cap in v4 is what exposed the absolute
  tolerance bug and let Pipeline B reach roughly 258 TeV.
- Tradeoff to keep in view: the observed min/max is a finite-sample statistic, so
  rejecting on it truncates generated support at a sample-dependent point and
  flatters tail metrics. A physics-motivated ceiling would be preferable if one can
  be stated; until then the FLUKA-observed envelope is the defensible bound.
- Guard artifacts change hash, so guards must be refitted into a new version
  directory before this takes effect. Existing v4 artifacts still declare
  `diagnostic_only`.

## All-FLUKA envelope diagnostic generation

### Changed

- Added generation purpose `envelope_diagnostic`: the same checkpoint, the same
  generation seed (1556), and the same validation reference as a normal
  generated-validation run, but bounded by `guard_all_ref.json` instead of
  `guard_train_ref.json`.
- `resolve_generation_config` and `_validate_guard_role` accept the new purpose and
  require the all-clean guard with `action=operational_reject` for it.
- The resolved config and the generation manifest now carry `selection_allowed`,
  true only for `purpose=validation`.
- `evaluate_generated_root_files` gained `write_plots`. The diagnostic path runs
  metrics-only and records `plots_skipped: true`; the numbers are identical.
- The evaluation report propagates `selection_allowed` and `generation_purpose`
  from the generation manifest.
- `select_model4_validation_winner.py` refuses any evaluation carrying
  `selection_allowed: false` and names the purpose in the error.
- `create_model4_validation_configs.py` gained `--purpose` and `--dry-run`.
  Diagnostic configs resolve to
  `resolved_configs/model4_envelope_diagnostic_all_guard`.
- Added `scripts/compare_model4_guard_envelopes.py`, which reuses the shared
  `selection_metrics` so the comparison cannot drift from the real ranking, and
  flags `energy_distance` as noise-dominated rather than silently dropping it.

### Decision or note

- The teacher's argument is that the all-clean envelope is what FLUKA can actually
  produce, is frozen forever, and should therefore be fixed as ground truth. That is
  defensible for production, and the project already lets the all-clean envelope
  reject for MuonDIS.
- It is not adopted for selection, for one reason only: the all-clean envelope
  contains validation and test rows, so using it to shape generation would make the
  held-out-test claim false. The measured cost of keeping the train envelope is
  small; `Train versus All-FLUKA Guard` records bound differences of about 1.4% in
  2022, 1.3% in 2023, and 2.9% in 2024, with reference rejection under 0.1% either
  way.
- The diagnostic run turns that argument into a measurement rather than an opinion.
  If the metric differences land inside the FLUKA noise floor, the choice is shown
  to be immaterial and the question closes.
